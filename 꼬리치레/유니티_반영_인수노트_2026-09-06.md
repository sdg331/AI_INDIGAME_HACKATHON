## 2. 임포트 규약 (이번에 통일한 것)

- **그리드 슬라이스.** 기존에는 자동(타이트) 슬라이스라 프레임마다 실루엣 크기가 달라 중심이 튀었다. 모든 캐릭터 시트를 셀 단위(64×64 · 80×64 · 96×80)로 다시 잘랐다. 스프라이트 이름과 내부 ID는 그대로라 기존 클립 참조는 깨지지 않았다.
- **피벗.** 캐릭터는 캔버스 바닥에서 32px 위 = 64px 캔버스 (0.5, 0.5), 80px 캔버스 (0.5, 0.4). 기존 타이트 슬라이스의 중심과 1px 이내로 같아 프리팹 오프셋을 건드리지 않았다. 캔버스가 달라도 발 위치가 같다(플레이 캡처로 확인).
- **PPU.** 보스 60(기존 값 유지), 나머지 100(기존 값 유지). 보스 Visual 스케일 2 · 플레이어 Square 3.12 · 고블린 Square 2.5 → 월드 높이 보스 2.13 · 플레이어 2.0 · **고블린 1.6.** 고블린이 기획(전부 64px 동일)보다 20% 작다. 의도가 아니면 고블린 Square 스케일을 3.12로.
- **이펙트 피벗**은 `이펙트_정렬표.md`의 기준점을 그대로 넣었다(예: 발밑 이펙트 = 하단 중앙). 4절 참조.
- 프레임 시간은 전부 **임시값**(미리보기 GIF · `_build.json`). 신규 클립은 60fps + 마지막 프레임 홀드 키라 `clip.length = 합계 + 1/60초`. 기존 클립(Idle · Run · Hit · phase · Walk · Idle1 · PlayerWalk · Roll · Playerattack)은 12fps 그대로.

## 3. 캐릭터별 연결표

### 3-1. 보스 — `Animation/Boss/Boss.controller` (Prefab/Boss.prefab › Visual)

| 코드가 세팅 | 파라미터 | 상태 · 클립 | 비고 |
|---|---|---|---|
| `SetTrigger("HeartSlash")` 등 6종 | HeartSlash · DoubleSlash · HeartBullet · MagicRing · DashSlash · MagicBerserk (trigger) | AnyState → 같은 이름 상태 → 끝나면 Idle | 신규 |
| `SetBool("Groggy")` | Groggy (bool) | true → Groggy(마지막 프레임 정지 유지), false → Idle | 신규 |
| `SetTrigger("Hit")` | Hit | AnyState → Hit → Idle | **기존엔 Entry에서만 연결돼 실제로 재생되지 않았음** → AnyState 연결 추가, Hit.anim · phase.anim loop 해제 |
| `SetTrigger("PhaseTransition")` | PhaseTransition | AnyState → phase → Idle | 위와 동일 |
| `SetBool("IsMoving")` | IsMoving | Idle ⇄ Run | 기존 |
| `SetTrigger("Attack")` | Attack | 파라미터만 (소비 없음) | 코드가 패턴마다 같이 쏘므로 경고 방지용 |
| — | Walk.anim | 클립만 | 코드에 걷기/달리기 구분 없음 |
| `HeartRain` | 없음 | 없음 | 시트 없음. 인스펙터에서 추가하면 애니 없이 동작 → HeartBullet으로 매핑하거나 시트 추가 |

`Boss.prefab`의 `Square`(흰 네모 플레이스홀더)는 **비활성화**했다(삭제 안 함).

**튜닝 필요 (플머 값):** 공격 클립 6종 모두 판정 프레임이 **0.32초**에 온다. `EnsureDefaultPatterns`의 telegraphTime(0.40~0.70초)보다 빨라 화면 타격이 데미지보다 먼저 나오고, 클립이 telegraph+recovery보다 짧아 패턴 중간에 Idle로 돌아간다.

| 패턴 | 클립 길이 | telegraph + recovery |
|---|---|---|
| HeartSlash | 0.88 | 1.00 |
| DoubleSlash | 1.01 | 1.20 |
| HeartBullet | 0.88 | 1.05 / 0.75 |
| MagicRing | 0.78 | 0.80 |
| DashSlash | 0.81 | 1.20 |
| MagicBerserk | 1.19 | ~2.4 |
| phase | 0.67 | phaseTransitionDuration 1.5 |

telegraphTime을 0.32초 쪽으로 줄이거나, `sheets_spec`의 예고 3프레임을 늘려 클립을 다시 뽑으면 된다(프레임 번호 기준은 `보스_공격패턴문서.md` 4~7절).

**권장 코드:** `TakeDamage`가 매 피격마다 `Hit`를 쏘므로 경직 면역 중에도 공격 애니가 끊긴다. 실제 경직이 적용될 때만 `SetTrigger(Hit)`, `EnterFinalGroggy`에서 `ResetTrigger(Hit)`.

### 3-2. 고블린 — `Sprite/Player/Enemy/MeleeEnemyAI.controller` (Prefab/MeleeEnemyAI.prefab › Square)

| 코드가 세팅 | 파라미터 | 상태 · 클립 | 비고 |
|---|---|---|---|
| `Attack` + `IsAttacking` | Attack(trigger) · IsAttacking(bool) | → Attack(Temp4 11프레임, 접촉 Temp4_6 = 0.50초 = attackWindupTime, 총 1.45초) → Idle1 | Attack.anim을 11프레임으로 재구성. 기존 5프레임 판은 셀 1~5만 잘라 쓴 것 |
| `Hit` | Hit(trigger) | AnyState → Hit(GoblinHit 0.42초) → Idle1 | 신규. 연타 시 다시 재생되게 자기 전환 허용 |
| `Groggy` / `Incapacitated` | bool 2개 | 둘 중 하나 true → Groggy(Temp1, 마지막 프레임 유지), 둘 다 false → Idle1 | 신규 |
| `IsMoving` | IsMoving | Idle1 ⇄ Walk | 기존 |
| `Speed` · `Grounded` · `Dead` | 파라미터만 | — | Dead 시트 없음(사망은 기획상 없음) |

`MeleeEnemyAI.prefab`의 `animator` · `characterSprite` 필드를 **Square로 명시 연결**했다. 이전엔 비어 있어 `GetComponentInChildren`이 비활성 자식 `Attacck`의 Animator를 잡았고, 그래서 파라미터가 하나도 안 먹고 flipX도 안 됐다.

**필수 코드 수정:** `Groggy` bool을 그로기 타이머(약 196행)에서만 false로 내린다. `TakeDamage` · `ApplyPushback` · `Incapacitate` · `Die`로 그로기를 벗어날 때는 그대로 true라, 그로기 중 한 대 맞으면 애니메이터가 Groggy 상태에 갇힌 채 추격·공격한다. `CancelAttack()` 안에 `SetAnimatorBool(GroggyHash, false)` 한 줄이면 된다.

### 3-3. 플레이어 — `Animation/Player/Player.controller` (Prefab/Player.prefab › Square)

| 코드가 세팅 | 파라미터 | 상태 · 클립 | 비고 |
|---|---|---|---|
| `SetBool("Guard")` | Guard | Idle · PlayerWalk · Jump · Land · PlayerRoll · Playerattack → Guard(PlayerGuard, 마지막 자세 유지), false → Idle | 신규. **AnyState가 아닌 상태별 전이**인 이유는 아래 |
| `SetTrigger("ParrySuccess")` | ParrySuccess | AnyState → Parry(PlayerParry 0.68초) → Guard 유지 중이면 Guard, 아니면 Idle | 신규 |
| `SetBool("Parry")` | Parry | 파라미터만 | 그래프에서 안 씀 |
| `SetTrigger("Hit")` | Hit | 파라미터만 | 플레이어 피격 시트 없음 |
| `Roll` · `Attack` · `Jump` · `IsWalking` 등 | 기존 | 기존 | 손대지 않음 |
| **코드 미발동** | Skill · Attack2 · Attack3 · FallRecover (trigger) | AnyState → 각 상태(PlayerSkill · PlayerAttack2 · PlayerAttack3 · PlayerFallRecover) → Idle | 상태는 준비됨. **코드에서 SetTrigger만 하면 된다** |
| — | PlayerRun.anim | 클립만 | 코드에 걷기/달리기 구분 없음 |

Guard를 AnyState로 걸면 패리 성공 순간에도 코드가 Guard=true를 유지하므로 Parry 반응이 1프레임 만에 Guard로 덮인다. 그래서 진입 가능한 상태에서만 Guard로 들어가게 했다. 패리 연속 성공 시 ParrySuccess가 대기 상태로 남아 반응이 한 번 더 재생될 수 있다 → `ResetTrigger` 권장.

## 4. 이펙트 프리팹 — `Prefab/Effect/FX_*.prefab`

구조: 루트에 SpriteRenderer(Sprite-Lit-Default, Push.prefab과 같은 머티리얼) + Animator(1상태 컨트롤러). **Instantiate 하면 즉시 재생, 아무도 파괴하지 않는다.** 단발은 클립 길이 후 Destroy, 루프(GroggyHaste · GroggyLoop)는 상태 종료 시 Destroy.

스케일: 플레이어용 (3.12, 3.12, 1) = 플레이어 Square 스케일. 적용 이펙트(GroggyEnter · GroggyLoop)는 (2.5, 2.5, 1) = 고블린 Square. **캐릭터 비주얼의 자식으로 붙이면 스케일이 곱해지므로** 부모 없이 위치만 따라가거나 localScale을 1로.

오프셋은 픽셀 단위(PPU 100 → 0.01유닛/px에 비주얼 스케일을 곱해 월드로. 예: +6px → 6 × 0.01 × 3.12 = 0.19유닛). 좌우 반전은 `flipX`.

| 프리팹 | 용도 · 코드 훅 | 부착 지점 (캐릭터 피벗 기준 px) | 렌더 |
|---|---|---|---|
| FX_BurstCore | 폭발적 무력화 코어 · `UseExplosiveIncapacitation` | 주인공 발밑 (0, 0) | 앞 |
| FX_BurstRingS / M / L | 폭발적 무력화 링(연격량 S 15~24 · M 25~39 · L 40+, 초안) · 코어와 동시 | 주인공 발밑 (0, 0) | **뒤** |
| FX_GroggyHaste | 그로기 가속 · `UseGroggyAcceleration` 지속 동안 루프 | 주인공 손 (+6, +5) | 앞 |
| FX_GroggyEnter | 그로기 진입 · `EnterGroggy` / `Incapacitate` | 적 피벗 (0, 0) | 앞 |
| FX_GroggyLoop | 그로기 유지 루프(알파 70% 적용됨) | 적 피벗 (0, 0) | 앞 |
| FX_SwordSwap | 검 스왑 · `TrySwapEquippedSword` | 주인공 손 (+6, +5) | 앞 |
| FX_OathBreak | 맹세 위반 · `OathSystem.onOathViolated` | 주인공 손 (+6, +13) | 앞 |
| FX_SkillSwirl | 스킬 발동 소용돌이 · Skill 트리거와 동시 | 플레이어 Square와 **같은 위치·스케일·flipX** (몸 시트와 같은 셀·피벗) | 앞 |
| 기존 push · DashSheet · Slash | 밀어내기 · 돌진 · 참격 파동 | 기존 그대로 | — |
| `_Unused/` FX_TauntRange · TauntMark · Pull · ChainFinish · TimeStop | 삭제된 유물(도발 · 끌어당김 · 연쇄 마무리 · 시간 정지)용. **쓰지 않음** | — | — |

## 6. 같이 발견한 것 (이번 작업과 별개)

- **TestScene에 플레이어가 둘.** 씬의 `Player (1)`이 활성인 채로 StageManager가 `Player(Clone)`을 또 스폰한다. 플레이어 공격이 다른 플레이어를 때려 `[맹세 위반] 선제 공격: 'Player(Clone)'` 로그가 뜨고 HUD가 HP 0/100을 보여준다. `Player (1)`을 끄거나 `reuseExistingPlayer`로 처리.
- **2TestScene의 `boss`** 오브젝트는 Animator 없이 BossAI만 붙은 수동 배치라 애니메이션이 재생되지 않는다. `Boss.prefab` 인스턴스로 교체 권장. 실제 흐름(TestScene → StagePrefab2 4 → Boss.prefab)은 정상.
- **Build Settings**에 없는 `SampleScene.unity`가 등록돼 있다.
- TestScene이 에디터에서 dirty로 표시될 수 있다. 작업 중 임시 오브젝트를 만들었다 지운 흔적이며 실제 변경은 없다. 저장 전 확인.
- `Player.prefab` · `MeleeEnemyAI.prefab`의 SpriteRenderer `m_Size` 1 → 0.64, `StagePrefab2 4.prefab`의 Square m_Size 오버라이드는 재저장 부작용(DrawMode Simple이라 영향 없음).
- 작업 전 원본 백업: `%LOCALAPPDATA%\Temp\claude\...\scratchpad\backup\` (Sprite · Animation · Prefab). 되돌릴 일이 있으면 요청.
