## 2. 구조 — 어떻게 나눠 썼나

```
사용자 ──지시──▶ 비서 세션 (claude-86)
                  │  문서화 · 계획 · 프롬프트 · 조정 · QA · 통합
                  │
                  ├─ 메시지 ─▶ D1 UI 목업      (claude-04)
                  ├─ 메시지 ─▶ D2 보스 문서    (claude-71)
                  ├─ 메시지 ─▶ D3 연출 기획서  (claude-d0 정본 / claude-28 대안)
                  ├─ 메시지 ─▶ A1 주인공 도트  (claude-8d) → E2 고블린 재배정
                  ├─ 메시지 ─▶ A2 적 도트      (claude-83) → E1 스켈레톤 재배정
                  ├─ 메시지 ─▶ A3 보스 도트    (claude-1b)
                  └─ 메시지 ─▶ A4 이펙트       (claude-8e)
사용자 ──직접 지시──▶ 각 병렬 세션 (공격 재작업 · 얼굴 방향 · 보스 v8 · 방어/패링 추가 등)
```

- **비서 세션**은 파일을 거의 만들지 않고 「무엇을 누가 어떤 순서로」를 잡았다. 예외는 적 v1 애니메이션(사용자가 직접 시켰을 때)과 리스트 · 목록 문서.
- **병렬 세션**은 각자 자기 폴더/파일만 쓴다. 공통 문서(전체문서 · 허브 · CLAUDE.md)는 읽기 전용. 이 규칙 덕에 8세션이 동시에 돌아도 충돌은 1건(연출 기획서 중복)만 났다.
- **세션 간 통신**은 Claude Code의 세션 메시지 기능으로 했다. 비서가 각 세션에 「어떤 작업이냐」를 물어 이름을 확인하고, 프롬프트와 동기화 신호를 직접 넣었다.

## 4. 상세 사례 — 적 애니메이션 파이프라인 (사람이 준 이미지 → 게임 시트)

사용자가 이미지 생성기로 뽑은 캐릭터 시트 2장(1254×1254, 검정 배경, 4방향 · 이동 8프레임 · 대기 · 달리기 · 공격 · 피격 · 스킬 셀)을 넣었다. 비서가 Python으로 처리했다.

**파이프라인**
1. 밝기 임계 + 연결 성분으로 셀 17개 자동 탐지 → 역할 배정(사방향 4 · 이동 8 · 대기 · 달리기 · 공격 · 피격 · 스킬)
2. 배경 제거: 가장자리에서 이어진 어두운 영역 플러드필 + 다리 사이처럼 막힌 순수 검정(면적 400px 이상) 제거(눈구멍은 보존)
3. 바닥 그림자 타원 제거 + 타원 중심 x를 **앵커**로 기록(포즈가 바뀌어도 발 위치가 튀지 않게)
4. 고블린 공격 셀의 흰 참격 호 제거(크기 · 형태 기준 성분 제거, 칼날은 보존)
5. 프리멀티플라이 BOX 축소 → 키 58px → 24색 공통 팔레트 양자화, 알파 임계(AA 없음)
6. 프레임 합성: 대기(호흡 1px), 이동(시트 프레임 + 바운스), 공격 10(예고 5 · 스미어 · 접촉 · 회수 — 기울임 · 스케일 · 이동으로), 피격(플래시 · 밀림), 그로기(진입 3 · 멈춤 · 유지 2)
7. 시트 PNG + 4배 GIF + README(프레임 표 · 규약 · 한계 · 질문) + 재생성 스크립트

**반복 개선 로그 (5회)**

| 회 | 발견한 문제 | 수정 |
|---|---|---|
| 1 | 다리 사이 검은 배경 잔존 · 그림자 잔여 · 참격 호 미제거 | 배경이 순수 검정임을 샘플링으로 확인 → 색 기준 직접 제거. 참격 호 면적 기준 6000→1200 |
| 2 | 참격 호 조각 3개 중 큰 것만 제거됨 | 성분별 면적 측정(2570 · 546 · 1008) → 800 초과만 제거, 546은 칼날로 보존 |
| 3 | 몸에서 떨어진 파편 제거 규칙(500px)이 **스켈레톤 가는 다리를 지움** | 캐릭터별 파라미터화(스켈레톤 120 · 고블린 500) |
| 4 | 그림자 명도 범위를 넓히자 스켈레톤 정강이가 그림자로 판정됨 | 「차가운 회색만」 조건 시도 → 고블린 그림자 잔여 재발 → **캐릭터별 임계**(스켈레톤 125+cool, 고블린 150)로 분리 |
| 5 | 고블린 칼날이 참격 호와 함께 지워짐 | 면적 800 복귀 + 세로로 긴 밝은 조각만 별도 제거 |

**한계를 그대로 적음.** v1 README에 「직접 그린 프레임은 없다. 원본 포즈만 재조합했다」, 「이동이 핑퐁」, 「공격 예고는 상체 기울임만」을 명시했고, 이것이 그대로 E1 · E2 프롬프트의 작업 목록이 됐다.

## 9. 다음에 같은 방식으로 할 때

1. **세션에 이름표를 먼저 붙인다.** 자동 이름(claude-8e 등)은 작업을 알 수 없어 8세션에 일일이 물어야 했다. 프롬프트 첫 줄에 「너는 D2다」를 넣고 시작하면 된다.
2. **같은 파일을 두 세션에 주지 않는다.** D3 중복은 프롬프트를 두 번 붙인 결과였다. 배정표를 먼저 쓰고 붙인다.
3. **QA 이미지는 사람(또는 비서)이 직접 본다.** 세션 자체 QA 점수(68~100)와 실제 결함(잔여 블록 · 얼굴 방향)은 별개였다.
4. **전달 후 재생성을 추적한다.** 얼굴 방향 수정처럼 전달된 파일이 조용히 바뀌는 경우가 있다. 리스트에 전달 시각을 적어 두면 잡힌다.
5. **v1은 남긴다.** 재조합 v1 → 직접 그린 v2로 갈 때 v1 README의 「한계」가 곧 v2 프롬프트가 됐다.
